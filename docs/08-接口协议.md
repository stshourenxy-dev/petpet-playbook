# 08 · 接口协议：宠物包即数据契约

> 本文档回答：一个宠物包由什么组成、pet.json 的完整 Schema、哪里可以定制。
> 核心结论：**宠物 = 目录 + 配置 + 精灵表 + 活动记录**，全部是数据，与代码解耦。

---

## 1. 宠物包目录结构

```
~/.petpet/pets/<宠物名>/
├── pet.json           # 宠物配置（核心契约）
├── activity.json      # 活动记录（心情日记数据源）
├── idle.png           # 单帧动作可直接放根目录
├── wiggle.png         # 多帧动作精灵表
├── sleep/
│   └── sleep_sprite.png  # 或放子目录（file 字段指定）
└── (birthdays.json)   # 生日彩蛋（预留）
```

规则：单帧动作 = PNG 文件；多帧动作 = 精灵表 PNG（可放子目录，`file` 字段指向）。

---

## 2. pet.json Schema

```json
{
  "id": "redshao",
  "name": "红苕",
  "theme": "bro",
  "actions": {
    "idle": {
      "file": "knead/knead_sheet.png",
      "frames": 12,
      "fps": 5,
      "weight": 150,
      "pingpong": false,
      "frameWidth": 1024,
      "frameHeight": 576,
      "scale": 1.0,
      "loop": true
    }
  }
}
```

### 2.1 顶层字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 宠物标识（= 目录名） |
| name | string | 显示名 |
| theme | string | 主题（bro/sis/orange） |
| actions | object | 动作配置表（键 = 动作名） |

### 2.2 动作字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| file | string | ✅ | — | 精灵表路径（相对宠物目录） |
| frames | number | ✅ | — | 帧数（横向切片数） |
| fps | number | — | 5 | 播放帧率 |
| weight | number | — | 10 | 随机权重（性格量化） |
| pingpong | boolean | — | false | 往返播放 |
| frameWidth | number | ✅ | — | 单帧宽（= 表宽/帧数） |
| frameHeight | number | ✅ | — | 单帧高 |
| scale | number | — | 1.0 | 显示缩放 |
| loop | boolean | — | true | 循环播放 |

### 2.3 动作名注册表（标准 8 动作）

```
idle     待机（抱熊）      sleep    睡觉
sniff    嗅闻              wiggle   撒娇
run      奔跑              belly    露肚躺
poop     拉粑粑            stretch  伸懒腰
```

自定义动作 = 任意新键 + 精灵表，无需改代码。

---

## 3. 精灵表契约

| 规则 | 值 | 违反后果 |
|------|-----|---------|
| 单帧正方形 | 1024×1024（常规） | 切片错位 |
| 横版场景帧 | 1024×576 | 窗口 letterbox |
| 横向排列 | 帧 i 位于 x=[i×w, (i+1)×w) | 切片错位 |
| **总宽上限** | **≤16384px** | **WebGL 黑屏**（见 07） |
| 透明底 | PNG alpha | 背景残留 |

## 4. 对接其他桌宠生态（Codex Pet 示例）

> 宠物包格式不统一是生态现状——本文档定义的是本项目 viewer 的契约；其他桌宠壳各有各的格式。**素材管线的产物可以适配多个壳**（见 05 工具可替换矩阵），本节以 Codex Pet 为例给出对接规格（格式规格来自公开资料核实，2026-08）。

### 4.1 Codex Pet 精灵图规格

| 参数 | V1（兼容老版） | V2（推荐） |
|------|---------------|-----------|
| 总尺寸 | 1536 × 1872 | 1536 × 2288 |
| 网格 | 8 列 × 9 行 | 8 列 × 11 行 |
| 每格 | 192 × 208 | 192 × 208 |
| 格式 | spritesheet.webp（无损） | spritesheet.webp（无损） |
| 背景 | 必须完全透明（alpha=0） | 必须完全透明（alpha=0） |

V2 多出的 2 行预留给更多状态。对应 pet.json 需声明 `spriteVersionNumber: 2` + `spriteSheet`（宽高/行列/格尺寸）+ `states`（每状态 = 行号 + 帧数 + 是否循环）。

### 4.2 对接要点

1. **make_sheet 参数化输出**：网格 8×11、每格 192×208、居中缩放不拉伸、空位保持透明——只需改输出参数，管线逻辑不变
2. **背景透明**：RGBA 输出，背景 alpha 严格为 0；抠图用 rembg 语义分割（色度抠图对白毛失效的教训见 07）
3. **边缘清理**：半透明碎边（alpha<30）置零 + 去除背景溢色残留

### 4.3 三个适配注意点

1. **语义映射是使用方的事**：Codex Pet 的状态是「AI 助手状态」（thinking/building/failed/review…），与宠物行为动作（睡觉/撒娇/拉粑粑…）不是一一对应。格式能对接，动作映射需自行设计——宠物动画强塞进 AI 状态机会错乱
2. **分辨率代价**：192×208 小格 vs 本项目常规 1024 单帧——高清素材缩进去细节损失明显
3. **背景要求冲突**：保留背景的场景帧（如横版待机帧）不满足「完全透明」硬要求，此类素材需单独处理或不可用

### 4.4 启示

- 「宠物即数据包」在不同壳之间并不互通——**格式标准化是空白，也是机会**
- 管线产物可喂多个壳（本项目 viewer / Codex Pet / 其他），素材生产与消费端解耦的设计收益在此兑现

## 5. activity.json：心情日记数据源

```json
[
  {
    "time": "2024-01-01T12:00:00+08:00",
    "action": "wiggle",
    "mood": "开心",
    "text": "红苕扭着屁股撒欢，尾巴摇成小风扇。"
  }
]
```

| 字段 | 说明 |
|------|------|
| time | 动作发生时间 |
| action | 动作名 |
| mood | 心情标签（动作映射） |
| text | 心情文案（动作→文案表） |

**机制**：动作切换时 appendActivity 写入（同动作不重复记、idle 不记）；滚动上限 100 条；日记面板倒序展示 + 顶部"当前状态"实时同步。

**心情映射表**（动作 → mood/文案基调）：

| 动作 | mood | 文案基调 |
|------|------|---------|
| sleep | 安逸 | 蜷成一团睡着了 |
| sniff | 好奇 | 东闻闻西嗅嗅 |
| wiggle | 开心 | 扭着屁股撒欢 |
| run | 兴奋 | 撒腿就跑 |
| belly | 惬意 | 露肚皮晒太阳 |
| poop | 心虚 | 偷偷拉粑粑 |
| stretch | 舒坦 | 伸了个大大的懒腰 |

## 6. 可定制点标注（授人以渔）

| 定制需求 | 改哪里 | 是否改代码 |
|---------|--------|-----------|
| 换宠物 | 加目录 + pet.json | 否 |
| 加动作 | 精灵表 + actions 新键 | 否 |
| 调动作节奏 | fps/帧数 | 否 |
| 改性格 | weight | 否 |
| 改心情文案 | 文案表 | 代码（集中在一处映射表） |
| 改主题 | pet.json theme + 样式 | 代码（样式文件） |
| 生日彩蛋 | birthdays.json | 代码（主进程检测逻辑，预留） |

**设计原则**：90% 定制通过数据完成；剩下 10%（文案表/样式/检测逻辑）集中在代码的少量可读位置。

---

## 7. 本文档可自行修改的点

1. 标准 8 动作是基线，自定义动作随意加
2. activity.json 上限（100 条）可按需调
3. birthdays.json 结构预留，实现时可扩展（关系字段：主人/狗狗/朋友）
