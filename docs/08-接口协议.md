# 08 · 接口协议：宠物包即数据契约

> 本文档回答：一个宠物包由什么组成、pet.json 的完整 Schema、哪里可以定制。
> 核心结论：**宠物 = 目录 + 配置 + 精灵表 + 活动记录**，全部是数据，与代码解耦。
> 当前契约版本：**v3**（2026-08-08）。
> 机器可读契约见 [schema/pet.schema.json](../schema/pet.schema.json)——本文档字段表由它生成，两者以 schema 为准。
> 校验：`python pipeline/validate_pet.py <宠物包目录>`（缺字段/精灵表缺失/纹理超限都会报错，不再静默失败）。

---

## 1. 宠物包目录结构

```
~/.petpet/pets/<宠物名>/
├── pet.json           # 宠物配置（核心契约）
├── activity.json      # 活动记录（心情日记数据源）
├── idle.png           # 单帧动作可直接放根目录
├── wiggle.png         # 多帧动作精灵表
├── sleep/
│   └── sleep_sprite.png  # 或放子目录（file 字段指定）
└── (birthdays.json)   # 生日彩蛋（预留）
```

规则：单帧动作 = PNG 文件；多帧动作 = 精灵表（PNG 或 WebP 无损，可放子目录，`file` 字段指向）。
> 体积提示：WebP 无损比 PNG 小 30-40%（viewer 的 MIME 表已支持 `.webp`），仓库示例素材优先用 WebP（见 CONTRIBUTING「示例素材上限」）。

### 1.1 宠物包导入（viewer 内置，2026-08-10）

> 功能来源：用户反馈——宠物主人安装素材包困难（需手动复制目录到 `~/.petpet/pets/`，红苕爸爸实测暴露），故提供双击导入入口。

托盘菜单「📦 导入宠物包」支持两种来源：

| 来源 | 操作 | 流程 |
|------|------|------|
| 目录 | 选择已解压的宠物包目录 | 校验 → 复制到 `~/.petpet/pets/<id>/` |
| 压缩包 | 选择 `.petpack` / `.zip` | 系统 unzip 解压 → 定位包根 → 校验 → 移动 |

- **压缩包约定**：顶层或单层子目录内含 `pet.json` 即可（zip 根目录名不要求等于 id，导入时按 pet.json 的 `id` 命名）
- **导入前校验**（JS 轻量版，对齐 `pipeline/validate_pet.py` 核心检查项）：pet.json 可解析、version 合法、`id` 匹配 `^[a-z0-9_-]+$`、actions 非空、精灵表文件存在、帧宽×帧数与实际宽均 ≤16384px
- **导入后**：自动刷新托盘菜单并切换到新宠物；目标目录已存在时覆盖导入
- 实现：`viewer/pet-import.cjs`（主进程模块，含单测 `viewer/tests/pet-import.test.ts`）

## 2. pet.json Schema

```json
{
  "version": 3,
  "id": "redshao",
  "name": "红苕",
  "theme": "bro",
  "bubbles": ["汪！", "摸摸我～", "今天也要开心哦！"],
  "actions": {
    "idle": {
      "file": "knead/knead_sheet.png",
      "frames": 12,
      "fps": 5,
      "weight": 150,
      "pingpong": false,
      "frameWidth": 1024,
      "frameHeight": 576,
      "scale": 1.0,
      "loop": true,
      "label": "待机",
      "diary": { "mood": "安逸", "text": "{name}抱着小熊待机，安静等主人。" }
    },
    "sleep": {
      "file": "sleep/sleep_sprite.png",
      "frames": 12,
      "fps": 5,
      "frameWidth": 1024,
      "frameHeight": 1024,
      "scale": 1.1,
      "transitions": { "stretch": 80, "idle": 20 }
    }
  }
}
```

> ⚠️ v3 起新增 `bubbles` / `transitions` / `label` / `diary` 四个可选字段（见 2.2），
> 旧宠物包（v2，无这些字段）**完全兼容**——viewer 未读到新字段时回退内置默认。
> 完整 v3 示例见 [examples/redshao-demo/pet.json](../examples/redshao-demo/pet.json)（含 `sleep→stretch` 转移链演示）。

### 2.1 顶层字段

| 字段 | 类型 | 说明 |
|------|------|------|
| version | number | 配置版本（当前 3，即 `"version": 3`） |
| id | string | 宠物标识（= 目录名，`^[a-z0-9_-]+$`） |
| name | string | 显示名 |
| style | string | 风格标签（如 `illustration`，仅作元信息，不参与渲染） |
| theme | string | 主题（bro/sis/orange） |
| cellWidth / cellHeight | number | **后备帧尺寸**（旧字段）：仅当动作未提供 frameWidth/frameHeight 时用于切片计算；新宠物包建议直接用每动作的 frameWidth/frameHeight（见 2.2），顶层这两个字段可省略 |
| bubbles | array | **v3 新增**：互动气泡文案池（替代代码硬编码 BUBBLE_TEXTS；未写则用内置默认） |
| identity | object | **V2-A 新增（可选）**：身份事实——`{species, appearance: {...}, habits: {likes_ball: true}}`；描述"它是谁"，供未来行为映射与展示；缺省兼容旧包 |
| temperament | object | **V2-A 新增（可选）**：气质倾向——`{activity, clinginess, curiosity, independence}` 均为 0-1；调制随机行为权重（幅度 ±30%，钳制 0.7-1.3）；缺省/中性=原行为。例：clinginess 高 → wiggle/belly 概率↑，activity 高 → run 概率↑ |
| actions | object | 动作配置表（键 = 动作名） |

### 2.2 动作字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| file | string | — | — | 精灵表路径（相对宠物目录）；与 `sprite` 二选一，代码 `act.file \|\| act.sprite` |
| sprite | string | — | — | 精灵表路径的别名（与 `file` 等价，新旧宠物包都支持） |
| frames | number | ✅ | — | 帧数（横向切片数） |
| fps | number | — | 4 | 播放帧率（代码默认 4，即 `act.fps \|\| 4`） |
| weight | number | — | 0 | 随机权重（性格量化）。**默认 0 = 不参与随机演示**，要随机触发必须显式设置 > 0 |
| pingpong | boolean | — | false | 往返播放 |
| frameWidth | number | ✅ | — | 单帧宽（= 表宽/帧数） |
| frameHeight | number | ✅ | — | 单帧高 |
| scale | number | — | 1.0 | 显示缩放 |
| loop | boolean | — | true | 循环播放 |
| transitions | object | — | — | **v3 新增**：动作间转移权重（马尔可夫链：播完后按此表选下一动作；缺省则退回全局 weight 池）。如 `{"stretch": 80, "idle": 20}` = 播完 80% 接伸懒腰、20% 回待机 |
| label | string | — | — | **v3 新增**：菜单显示名（自定义动作在菜单里显示 label 而非原始动作 key） |
| diary | object | — | — | **v3 新增**：动作→日记心情文案（替代代码硬编码 ACTIVITY_TEXTS）。含 `mood`（心情标签）与 `text`（文案，支持 `{name}` 占位符替换为宠物名） |

> 字段表由 [schema/pet.schema.json](../schema/pet.schema.json) 生成——改 schema 后需同步本文档。

### 2.3 动作名注册表（标准 8 动作）

```
idle     待机（抱熊）      sleep    睡觉
sniff    嗅闻              wiggle   撒娇
run      奔跑              belly    露肚躺
poop     拉粑粑            stretch  伸懒腰
```

自定义动作 = 任意新键 + 精灵表，无需改代码。

### 2.4 转移链（transitions，v3）

行为链是**用数据表达性格**的核心手段（参考 Shimeji NextBehaviorList 思路，见 [11-同类项目借鉴](11-同类项目借鉴.md) §2.1）：

```json
"sleep": { "transitions": { "stretch": 80, "idle": 20 } }
```

- 随机触发 sleep 播完后，80% 概率接 stretch（睡醒先伸懒腰）、20% 回 idle
- **只对随机进入的动作生效**——用户手动切换的动作播完不自动转移（不打断手动操作）
- 无 transitions 的动作保持旧行为（播完回 idle）——旧宠物包逐字节兼容
- 链式可多跳：`sleep → stretch → idle`（每跳都是独立 transitions 表）

## 3. 精灵表契约

| 规则 | 值 | 违反后果 |
|------|-----|---------|
| 单帧正方形 | 1024×1024（常规） | 切片错位 |
| 横版场景帧 | 1024×576 | 窗口 letterbox |
| 横向排列 | 帧 i 位于 x=[i×w, (i+1)×w) | 切片错位 |
| **总宽上限** | **≤16384px** | **WebGL 黑屏**（见 [07-踩坑实录](docs/07-踩坑实录.md)） |
| 格式 | PNG（默认）/ WebP 无损（推荐省体积） | 解码失败黑屏 |
| 透明底 | PNG/WebP alpha 通道 | 背景残留 |

## 4. 对接其他桌宠生态（Codex Pet 示例）

> 宠物包格式不统一是生态现状——本文档定义的是本项目 viewer 的契约；其他桌宠壳各有各的格式。**素材管线的产物可以适配多个壳**（见 [05-素材管线](docs/05-素材管线.md) 工具可替换矩阵），本节以 Codex Pet 为例给出对接规格（格式规格来自公开资料核实，2026-08）。

### 4.1 Codex Pet 精灵图规格

| 参数 | V1（兼容老版） | V2（推荐） |
|------|---------------|-----------|
| 总尺寸 | 1536 × 1872 | 1536 × 2288 |
| 网格 | 8 列 × 9 行 | 8 列 × 11 行 |
| 每格 | 192 × 208 | 192 × 208 |
| 格式 | spritesheet.webp（无损） | spritesheet.webp（无损） |
| 背景 | 必须完全透明（alpha=0） | 必须完全透明（alpha=0） |

V2 多出的 2 行预留给更多状态。对应 pet.json 需声明 `spriteVersionNumber: 2` + `spriteSheet`（宽高/行列/格尺寸）+ `states`（每状态 = 行号 + 帧数 + 是否循环）。

### 4.2 对接要点

1. **make_sheet 参数化输出**：网格 8×11、每格 192×208、居中缩放不拉伸、空位保持透明——只需改输出参数，管线逻辑不变
2. **背景透明**：RGBA 输出，背景 alpha 严格为 0；抠图用 rembg 语义分割（色度抠图对白毛失效的教训见 [07-踩坑实录](docs/07-踩坑实录.md)）
3. **边缘清理**：半透明碎边（alpha<30）置零 + 去除背景溢色残留

### 4.3 三个适配注意点

1. **语义映射是使用方的事**：Codex Pet 的状态是「AI 助手状态」（thinking/building/failed/review…），与宠物行为动作（睡觉/撒娇/拉粑粑…）不是一一对应。格式能对接，动作映射需自行设计——宠物动画强塞进 AI 状态机会错乱
2. **分辨率代价**：192×208 小格 vs 本项目常规 1024 单帧——高清素材缩进去细节损失明显
3. **背景要求冲突**：保留背景的场景帧（如横版待机帧）不满足「完全透明」硬要求，此类素材需单独处理或不可用

### 4.4 启示

- 「宠物即数据包」在不同壳之间并不互通——**格式标准化是空白，也是机会**
- 管线产物可喂多个壳（本项目 viewer / Codex Pet / 其他），素材生产与消费端解耦的设计收益在此兑现

## 5. 活动记录：心情日记数据源

```json
[
  {
    "time": "2024-01-01T12:00:00+08:00",
    "action": "wiggle",
    "mood": "开心",
    "text": "红苕扭着屁股撒欢，尾巴摇成小风扇。"
  }
]
```

| 字段 | 说明 |
|------|------|
| time | 动作发生时间 |
| action | 动作名 |
| mood | 心情标签（动作映射） |
| text | 心情文案（动作→文案表） |

**机制**：动作切换时 appendActivity 写入（同动作不重复记、idle 不记）；滚动上限 100 条；日记面板倒序展示 + 顶部"当前状态"实时同步。

**v3 文案下沉**：mood/text 可由动作的 `diary` 字段定制（见 2.2）——代码内置的是默认值，宠物包可覆盖。未写 diary 的动作用内置映射（见下方心情映射表）。

**心情映射表**（动作 → mood/文案基调，代码内置默认）：

| 动作 | mood | 文案基调 |
|------|------|---------|
| sleep | 安逸 | 蜷成一团睡着了 |
| sniff | 好奇 | 东闻闻西嗅嗅 |
| wiggle | 开心 | 扭着屁股撒欢 |
| run | 兴奋 | 撒腿就跑 |
| belly | 惬意 | 露肚皮晒太阳 |
| poop | 心虚 | 偷偷拉粑粑 |
| stretch | 舒坦 | 伸了个大大的懒腰 |

## 6. 校验器：写错不再静默失败

`pipeline/validate_pet.py` 在打包前校验宠物包（第 5 个管线脚本）：

```bash
python pipeline/validate_pet.py <宠物包目录>    # 校验 pet.json + 精灵表 + 纹理上限
python pipeline/validate_pet.py <pet.json>      # 同上
python pipeline/validate_pet.py --profile <画像.json>  # 校验画像 + 自动补派生比例
```

检查项（对应本文档各节）：

| 检查项 | 依据 |
|--------|------|
| id 正则、必填字段、类型 | §2.1/2.2 |
| 精灵表文件存在 | §3 |
| **纹理上限 16384px**（配置帧宽×帧数 & 实际文件宽双层） | [07-踩坑实录](07-踩坑实录.md) 铁律 #1 |
| 配置需求宽度 ≤ 文件宽度（防切片越界） | §3 |
| 画像 16 字段 + 派生比例自动计算 | [01-数据模型](01-数据模型.md) §3.3 |

配套：`pipeline/gen_prompt.py` 从画像生成提示词（第 6 个管线脚本，见 [02-特征与提示词](02-特征与提示词.md)）。

## 7. 可定制点标注（授人以渔）

| 定制需求 | 改哪里 | 是否改代码 |
|---------|--------|-----------|
| 换宠物 | 加目录 + pet.json | 否 |
| 加动作 | 精灵表 + actions 新键 | 否 |
| 调动作节奏 | fps/帧数 | 否 |
| 改性格 | weight / **transitions（行为链）** | 否 |
| 改菜单名 | label | 否 |
| 改心情文案 | **diary（动作级）** | 否（v3 起） |
| 改气泡文案 | bubbles | 否（v3 起） |
| 改主题 | pet.json theme + 样式 | 代码（样式文件） |
| 生日彩蛋 | birthdays.json | 代码（主进程检测逻辑，预留） |

**设计原则**：90% 定制通过数据完成；剩下 10%（主题样式/彩蛋检测逻辑）集中在代码的少量可读位置。

## 8. 本文档可自行修改的点

1. 标准 8 动作是基线，自定义动作随意加
2. activity.json 上限（100 条）可按需调
3. birthdays.json 结构预留，实现时可扩展（关系字段：主人/狗狗/朋友）
4. **改字段契约时**：先改 [schema/pet.schema.json](../schema/pet.schema.json)（机器可读为准），再同步本文档字段表
