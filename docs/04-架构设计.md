# 04 · 架构设计：Electron + PixiJS 的桌宠骨架

> 本文档回答：桌宠程序由哪些部分组成、数据怎么流、为什么这么分。
> 核心结论：**主进程管系统、渲染进程管画面、数据层管宠物**——三者解耦是后续所有功能扩展的地基。

---

## 1. 技术选型

| 层 | 技术 | 选型理由 |
|----|------|---------|
| 桌面容器 | Electron | 跨平台（macOS/Windows）、透明窗口、托盘、系统菜单原生支持 |
| 渲染引擎 | PixiJS | WebGL 精灵表动画、轻量（相对 Three.js）、2D 精灵动画最优解 |
| 数据 | JSON（pet.json + 精灵表 PNG） | 宠物即数据包，换宠物=换目录，不动代码 |

对比过 Tauri（WindowPet/wimipet 用）：更轻但生态较新，Electron 的透明窗口+托盘+原生菜单成熟度更高。本项目动画复杂度低，Electron 的体积劣势可接受。

---

## 2. 进程架构

```mermaid
graph TB
    subgraph 主进程 Main
        M1[Tray 托盘菜单]
        M2[原生右键菜单 Menu.popup]
        M3[提醒系统 reminder:set]
        M4[文件读写 pet.json/activity.json]
    end
    subgraph 渲染进程 Renderer
        R1[PixiJS 动画播放]
        R2[交互 单击/双击/拖拽]
        R3[气泡与面板 UI]
    end
    subgraph 数据层
        D1[~/.petpet/pets/&lt;宠物名&gt;/<br/>pet.json + 精灵表 + activity.json]
    end
    M1 <-->|IPC| R1
    M2 <-->|IPC| R1
    M3 -->|IPC| R2
    M4 <--> D1
```

| 进程 | 职责 | 关键点 |
|------|------|--------|
| 主进程 | 托盘、原生菜单、提醒调度、文件读写 | 系统级能力都在这里（macOS 菜单栏/Dock 图标） |
| 渲染进程 | 精灵表动画、交互、UI | PixiJS 播放，窗口透明 |
| preload | IPC 桥 | 上下文隔离，暴露 `petAPI` |

**为什么原生菜单走主进程**：Electron 透明窗口里 CSS 菜单装不下 12 项且做不出真毛玻璃——系统级 `Menu.popup` 自动定位、自动毛玻璃、不裁切（踩坑记录见 [07-踩坑实录](docs/07-踩坑实录.md)）。

## 3. 窗口设计

| 属性 | 值 | 说明 |
|------|-----|------|
| 尺寸 | 320×320 | 固定基准（WINDOW_W/H） |
| 透明 | 是 | 精灵表透明区域透出桌面 |
| 无边框 | 是 | 宠物本体即窗口 |
| 置顶 | 是 | 悬浮于工作区 |
| 鼠标穿透 | 动态切换 | 平时穿透（不挡工作），悬停/交互时解除 |

**适配逻辑**：`fit = min(窗口宽/帧宽, 窗口高/帧高)`——横版帧（1024×576）在正方形窗口里上下留白，竖版帧等比缩放。

## 4. IPC 通道表（主进程 ⇄ 渲染进程）

> 完整清单以 `viewer/preload.cjs` 为准（以下按功能分组，含全部通道）。

**宠物数据（`pet:`）**

| 通道 | 方向 | 用途 |
|------|------|------|
| `pet:list` | 渲染→主（invoke） | 列出宠物包（多宠自动发现） |
| `pet:load` | 渲染→主（invoke） | 加载 pet.json |
| `pet:file` | 渲染→主（invoke） | 读取精灵表文件（含路径边界校验） |
| `pet:loaded` | 渲染→主 | 宠物加载完成（托盘动作菜单同步） |
| `pet:action` | 主→渲染 | 动作切换指令（托盘/菜单触发） |
| `pet:switch` | 主→渲染 | 切换宠物通知 |
| `pet:setIgnoreMouse` | 渲染→主 | 鼠标穿透控制（透明区穿透桌面） |
| `pet:activity` | 渲染→主 | 写活动记录（红苕日记） |
| `pet:activity:list` | 渲染→主（invoke） | 读活动记录 |
| `pet:action:notify` | 渲染→主 | 动作切换通知（日记"当前状态"实时同步） |
| `pet:visibility` | 主→渲染 | 窗口显示/隐藏通知（隐藏时暂停动画，省电） |

**视图控制（`view:`）**

| 通道 | 方向 | 用途 |
|------|------|------|
| `view:setSize` | 渲染→主 | 设置窗口尺寸 |
| `view:move` | 渲染→主 | 移动窗口（拖拽） |
| `view:getPos` | 渲染→主（invoke） | 获取窗口位置 |
| `view:zoom` | 主→渲染 | 缩放通知 |
| `view:reset` | 主→渲染 | 重置大小通知 |

**提醒（`reminder:`）**

| 通道 | 方向 | 用途 |
|------|------|------|
| `reminder:set` | 渲染→主（invoke） | 设置提醒（自然语言时间解析，持久化到 ~/.petpet/reminders.json） |
| `reminder:fire` | 主→渲染 | 提醒到点触发（气泡 + 系统通知） |
| `reminder:list` / `reminder:del` | 主进程托盘菜单 | 查看/删除已设提醒（不经渲染进程） |

**其他**

| 通道 | 方向 | 用途 |
|------|------|------|
| `menu:showContext` | 渲染→主（invoke） | 弹出系统原生右键菜单（自动定位不裁切） |
| `diary:open` | 渲染→主 | 打开红苕日记独立窗口 |
| `open:reminder` | 主→渲染 | 托盘"提醒我"打开输入面板 |
| `test:action` | 主→渲染 | 测试动作（`--action` 命令行参数） |

## 5. 数据流：从宠物包到屏幕

```
启动
 ├─ 主进程读 ~/.petpet/pets/<宠物名>/pet.json
 ├─ 渲染进程按 pet.json 加载精灵表 PNG
 ├─ 按 act.frameWidth/frameHeight 水平切片（new PIXI.Rectangle）
 ├─ AnimatedSprite 按 fps 播放
 └─ 动作切换 → appendActivity 写 activity.json → 日记面板实时同步
```

**关键设计**：宠物包（pet.json + 精灵表 + activity.json）是**纯数据**，与代码完全分离——换宠物、加动作、调参数全部改数据不改代码。

## 7. 本文档可自行修改的点

1. **换容器**：Tauri/原生皆可，但透明窗口+托盘+原生菜单三件套是底线能力
2. **换渲染**：非 PixiJS 的 2D 引擎也可，精灵表切片逻辑通用
3. **改窗口尺寸**：WINDOW_W/H 是全局常量，适配逻辑自动跟随
