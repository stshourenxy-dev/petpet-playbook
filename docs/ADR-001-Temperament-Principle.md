# ADR-001: Temperament Principle（气质原则）

- 状态：**Accepted**（2026-08-09，V2-A 实施时确立）
- 关联代码：`viewer/src/temperament.ts`（V2-A 已实施）
- 关联设计：`docs/08-接口协议.md`（identity/temperament 字段）、V2-B Relationship Engine（未来）

## 决策（Decision）

> **Temperament modifies behavior probability, but never owns behavior decision.**
> **气质影响行为倾向，但不决定行为。**

任何"状态 → 行为"的映射（当前为 temperament，未来含 Relationship Engine），只能**调制行为的概率分布**，禁止**决定性地强制行为**。

## 上下文（Context）

V2-A 引入 temperament（activity/clinginess/curiosity/independence）调制随机行为权重。V2-B 将引入 Relationship Engine（亲密度/关系阶段）。若采用决定论映射：

```
❌ 亲密度 = 90 → 强制撒娇（决定论）
```

宠物行为变成"脚本"——可精确预测，但失去生命感。正确形态：

```
✅ 亲密度 ↑ → 撒娇概率 ↑（概率调制）
```

行为仍由概率驱动，状态只改变倾向。不确定性 = 生命感。

## 实现约束（Constraints）

1. **只调概率，不调仲裁**：调制仅作用于随机行为选择的权重（`effectiveWeight`）；`shouldPlay` 仲裁、用户主动操作（menu/reminder）优先级**不受调制影响**——用户操作永远是最高优先级（不变量）
2. **幅度克制**：调制系数钳制 [0.7, 1.3]（±30%），防止分布失衡（全撒娇/全跑）
3. **中性 = 默认**：缺省/中性状态（全 0.5）等于原行为，旧宠物包完全兼容
4. **零权重不激活**：`weight = 0` 的动作不被调制激活（调制只能缩放，不能从无到有）
5. **适用范围**：本原则约束所有未来的"状态 → 行为"映射——temperament（已实施）、Relationship Engine（V2-B 必须遵守）、Habit/记忆调制（V2-B+）

## 正面/反面模式（Patterns）

| 场景 | ❌ 违反（决定论） | ✅ 遵守（概率论） |
|---|---|---|
| 亲密度高 | 亲密度=90 → 必定撒娇 | 亲密度↑ → 撒娇概率↑ |
| 活跃度高 | 活跃=1 → 强制奔跑 | 活跃↑ → run 权重 ×1.3 |
| 熟悉主人 | 熟悉=365天 → 强制迎门 | 熟悉↑ → 互动类权重↑ |

## 后果（Consequences）

- **正面**：行为不可精确预测 → 宠物像生命；状态变化可被观察（"它越来越黏我"）但不可被脚本化
- **代价**：行为分布只能统计验证（直方图/长时间观察），不能断言"某状态必出某动作"——测试需概率化思维（分布对比而非单次断言）
- **与验证的关系**：V2-A 分布模拟（2 万次采样）是标准验证法——中性=默认兼容、极端方向正确

## 理由（Why）

决定论映射 = 状态机的死循环；概率调制 = 马尔可夫链的生命感。本项目从 Shimeji 转移链（马尔可夫）起家，本原则是该路线的正式化延续——**行为永远是概率的，状态只是概率的形状**。
