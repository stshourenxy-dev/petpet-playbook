# 03 · 需求梳理：从“想要个桌宠”到“数字宠物生命”

> 本文档还原需求推导全过程：**定位演进（桌宠→数字宠物生命）+ 功能推导（动作列表 0→9→8）**，每个动作为什么存在、素材怎么来的。
> 授人以渔要点：需求梳理分两层——**先定定位（做成什么），再定功能（做什么动作）**。参考对象决定产品天花板。

---

## 1. 定位演进：桌宠只是形式，数字宠物生命才是目的

### 1.1 阶段一：桌宠（最初的诉求）

最初的诉求只有一句：**「给红苕做个桌宠」**。此时“桌宠”是全部想象——一个会动的宠物形象趴在桌面上，能互动。

### 1.2 阶段二：竞品与情感场景比对（定位的动摇）

动手前看了三类参照，结论完全不同：

| 参照 | 看了什么 | 结论 |
|------|---------|------|
| 情感场景（抖音爆款视频） | 《我把去世四年的小狗藏进电脑里》——grief tech：宠物去世后的数字永生/告别 | 本项目定位应是「**活着的陪伴**」——让活着的宠物在桌面活蹦乱跳，比“告别”覆盖更广的情感需求 |
| 开源桌宠（GitHub 比对） | WindowPet（45+ 形象）、wimipet（AI 对话）等 | 功能堆砌（形象数量/AI 聊天/自定义），UI 粗糙，**没有可参考的生命感设计** |
| 大厂低门槛路线（豆包/即梦系） | 上传一张宠物照片 → 豆包「照片动起来」图生视频 → 会动的宠物视频 → 桌宠化（管线或第三方工具） | **形象还原而非生命还原**：解决“像不像”，不解决“行为/情绪/记忆”——动作是模板化的，没有性格定制 |

**案例剖析：低门槛一键路线（豆包类“一张图生成桌宠”）**

**具体怎么生成**（公开教程核实，多来源一致）：

1. **豆包「照片动起来」**（官方功能）：豆包 App → 新建对话 → 工具栏左滑找到「照片动起来」→ 上传宠物照片 → 输入动作指令（如“小狗摇尾巴”“让它眨眨眼”）→ 生成会动的宠物视频（免费，每天限次）
2. **桌宠化**：把动态视频做成桌宠——走本 Playbook 的素材管线（抽帧→抠图→精灵表，见 05），或用第三方“一张图生成桌宠”工具

整条链路：**一张宠物照片 → 会动的宠物视频 → 桌面宠物**。用户零输入、零技术，几分钟看到一个“会动的自家宠物”。

与本文方法论的对比：

| 维度 | 低门槛一键路线 | 本方法（特征→提示词→管线） |
|------|--------------|--------------------------|
| 用户输入 | 一张照片 | 特征收集表（16 字段）+ 提示词确认 |
| 形象还原 | 自动 | 半自动（主人核实设定图） |
| 行为定制 | 模板化动作 | 8 动作按宠物行为设计 |
| 性格表达 | 无 | 权重 = 性格量化 |
| 生命痕迹 | 无（只有形象） | 生日彩蛋/日记/提醒 |
| 可控性 | 低（生成即结果） | 高（每步可干预、可重生成） |

**启示**：低门槛路线赢在“像”，输在“活”——它复刻的是**形象**，不是**生命**。这与 §1.3 的定位洞察互相印证：目标是“数字宠物生命”时，一张图的便利是入口不是终点；特征收集的“麻烦”正是生命感定制的代价。

**从赛道全景看本文档的位置**：

1. **主流项目全部是「消费现成素材」**——VPet 创意工坊、PPet Live2D 库、Clawd 自带形象，**没有一家做「从真实宠物照片到桌宠」的生产管线**。拥挤的是成品桌宠，不拥挤的是生产方法。
2. **MiniCPM 官方二开 Clawd** = 「桌宠壳 + 自定义素材/模型」模式已被第三方团队实证——本文档「素材管线可喂任何壳」的设计（见 05 工具可替换矩阵）与生态方向一致。
3. **VPet 创意工坊（最大社区）验证「宠物包分发」模式成立**——与 Petdex 同为分发端繁荣，生产端仍是空白。
4. **HermesPet 的「AI 伴侣」与本文档的「宠物替身」是两条路**：它解决「AI 对话体验」，本文档解决「真实宠物的数字化身」——同赛道不同物种，互相不构成直接竞争。

> 数据来源：GitHub API 实测（2026-08-08）。Petto 因仓库未定位标注存疑，待确认后补全。

**适用边界（重要）**：以上比对**不是优劣之分，是目标之分**。如果你的需求就是“让我家猫在桌面上动一下”——低门槛路线更快更省，本方法对你**过度设计**，直接用豆包即可。本方法适合**目标不止于“会动”**的人：想要性格、想要记忆、想要生日彩蛋、想要“这是我家的狗而不是一只像它的狗”。选择哪条路，取决于你要的是形象还是生命，本文不替你选，只把两条路的代价摆清楚。

> 事实来源：豆包「照片动起来」功能（知乎专栏教程、B 站教程、媒体报道多来源一致）；第三方“一张图生成桌宠”工具（抖音教程）。各工具具体能力随版本迭代，以官方为准。

### 1.3 阶段三：定位洞察——参考数字宠物生命，不是桌宠

比对后得出关键判断：**最该参考的不是桌宠，而是贴近「数字宠物生命」的产品**——电子宠物/养成类/陪伴类产品的核心不是动画和功能，而是**生命感**：有状态、有情绪、会回应、会记住。桌宠只是形式，数字宠物生命才是目的。

这条定位决定了后续所有设计决策：

- 动作列表 = 宠物行为/情绪谱（不是功能列表）
- 权重 = 性格量化（不是随机播放概率）
- 生日彩蛋/日记/提醒 = 生命痕迹（不是功能堆砌）
- 数据模型 = 为“一只活的狗”建模（见 01），不是为“一个桌宠”建模

**授人以渔要点**：需求梳理先问“这到底是什么”（定位），再问“它要做什么”（功能）。参考对象选错，产品天花板就锁死了——参考桌宠得到桌宠，参考数字宠物生命才可能得到“活的宠物”。

## 2. 功能推导：从需求 grill 到动作定稿

### 2.1 需求 grill（功能层起点）

定位定完后，用多轮追问（grill）把功能需求拆开：

| 追问 | 答案 | 影响 |
|------|------|------|
| 要真实动物还是动画形象? | 皮克斯 3D 卡通(真实动画需 3D 骨架,不可行) | 决定素材管线 |
| 桌宠要做什么? | 陪着我,能互动 | 决定动作列表 |
| 用什么交互? | 单击/双击/右键/托盘 | 决定交互架构 |
| 素材从哪来? | AI 视频生成(即梦) | 决定成本模型 |
| 谁用? | 自己和朋友们的宠物 | 决定数据模型(多宠) |

## 3. 动作列表的推导

### 3.1 初版 9 动作（按宠物行为观察设计）

从"一只真实的边牧会做什么"出发,设计了 9 个动作:

| 动作 | 行为来源 | 用途 |
|------|---------|------|
| idle | 待机 | 默认状态(红苕特色:踩奶/抱熊) |
| sleep | 睡觉 | 长时间无互动 |
| sniff | 嗅闻 | 好奇状态 |
| wiggle | 扭动/撒娇 | 互动回应 |
| run | 奔跑 | 兴奋状态 |
| knead | 踩奶(抱熊) | **红苕独有动作**(前爪环抱泰迪熊) |
| belly | 露肚躺 | 信任/放松 |
| poop | 拉粑粑 | 淘气彩蛋 |
| stretch | 伸懒腰 | 状态切换过渡 |

设计原则:**每个动作对应一个真实行为场景**--待机/睡觉/好奇/撒娇/兴奋/放松/淘气/过渡,覆盖宠物情绪谱。

### 3.2 权重设计：宠物性格的量化

`weight` = 随机动作播放的概率权重。红苕 knead weight=150(默认动作权重),体现性格:**红苕最爱踩奶抱熊**。权重是宠物性格的量化表达--爱撒娇的狗 wiggle 权重高,爱睡的狗 sleep 权重高。

### 3.3 9 → 8：knead 并入 idle（设计决策）

演变过程:
1. 踩奶(knead)视频实际内容是**「狗环抱泰迪熊睡觉/依偎」的准静态画面**(帧间差异仅 0.01-0.018,无踩踏动作)
2. 与"踩奶 knead"动作名不符 → 讨论去留
3. **最终决策**:knead 从动作列表去掉,直接变成 idle 待机画面--红苕的待机就是抱熊
4. 代价:idle 变横版(1024×576)后待机狗缩小约一半--权衡后接受

```
9 动作 ──knead并入idle──► 8 动作(已定稿)
idle/sleep/sniff/wiggle/run/belly/poop/stretch
```

**基线规则**:动作列表定稿后,任何动作改动需重新评估。

## 5. 素材质量评估标准（生成后必查）

每个生成视频必须过检查点(参考 02 §4):

1. **全身完整入镜,包含尾巴**(最常翻车的点)
2. **形象未变**(棕白、白脸纹、白刘海--锚定 @图片1)
3. **动作符合预期**(动词链 vs 实际动作对比)
4. **背景干净**(纯色/纯白,便于抠图)
5. **循环首尾衔接**(差异度 < 0.05 为佳)

量化验证方法:抽帧后计算**帧间差异度**(像素差),静态/准静态视频差异度 < 0.02,合格动作视频 0.04-0.12。

## 6. 需求变更是常态（设计要留弹性）

需求在迭代过程中多次变更(实录):
- 撒娇:温柔版已部署 → 实测动作与预期不符 → 重抠图修复(白毛腿)→ 16帧定稿
- 伸懒腰:1帧静态 → 12帧动画
- knead:独立动作 → 并入 idle
- 奔跑:矮壮版(柯基感)被否 → 欢快版

**弹性来源**:数据模型(字段)+ 管线(素材可重生成)+ 配置(pet.json 可改)三者解耦--换素材不动代码,改动作不动数据模型。这是架构设计的核心收益(详见 04)。

## 7. 本文档可自行修改的点

1. 动作列表按自己宠物重新推导:观察你的宠物最常做什么、最有辨识度的行为是什么
2. 权重按性格调:爱睡的狗 sleep 权重调高
3. 素材升级优先级:先升级最常用的动作(idle 优先)
